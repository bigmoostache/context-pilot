What stands out

    Worst cases

    The rest of this page is about averages. This section ranks operations by their slowest single call, because one rare 200 ms call freezes the interface even when the average is a few microseconds. Each operation appears at the deepest level that still explains its spike, with the chain of parents above it. Select a row to open it in the call tree.

    mean worst call, colored by severity threshold

    A snapshot keeps no per-call timings, so “calls over” is a range: the fewest and the most calls that could have crossed the threshold while still matching the reported count, mean, variance and worst call. Severity follows the worst call: a frame drop from 16.7 ms, a stutter from 50 ms, a freeze from 100 ms. “No timers inside” means the op has no child timers, so adding some is the way to see which part blocks.

    Busy time by phase

    Total time of every top-level loop phase, idle excluded. The eight largest known phases keep a fixed color in every chart below, and any others are grey. Select a phase to open it in the call tree.

    Call tree

    Each block's width is its total time, nested under its parent. Children too narrow to draw are gathered into an outlined +N block. Select a block to zoom in and read its numbers below. A dot marks an op that is new since the previous snapshot.

    Self time

    Where busy time actually ends up: each op's time minus its timed children, at any depth, so a new timer appears here wherever it sits in the tree. When a parent spends time that none of its children cover, that remainder gets its own row, which shows where to add timers next. Select a row to open it in the call tree.
